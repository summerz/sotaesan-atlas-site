# 1회차 보완: 달리기와 축척 확인

- 날짜: 2026-11-07
- 범위: PlayCanvas + Ammo, `?scene=content&character=1`. 기존 카메라 구도·장면·인물 크기 유지.
- 요청: 달리기 제안 적용, 맵에 비해 인물이 작게 보이는 이유와 축척 확인.

## 적용

- PC: WASD 걷기, 왼쪽·오른쪽 Shift를 누른 채 이동하면 달리기. Shift 해제 시 걷기로 복귀한다. 화살표키는 기존대로 카메라 회전이다.
- 터치: 왼쪽 이동 터치를 시작점에서 85 CSS px 이상 밀면 달리고, 65 px 미만으로 되돌리면 걷는다. 경계에서 모드가 반복되는 것을 막기 위해 진입·해제 거리를 다르게 했다. 오른쪽은 둘러보기이며 추가 버튼은 없다.
- 속도: 걷기 설정 2 단위/초, 달리기 3.4 단위/초(1.7배). 대각선 입력 정규화와 기존 충돌·스트리밍 진입 검사를 그대로 거친다. 기존 비교 모드에는 달리기를 켜지 않는다.
- 모델의 `CharacterArmature|Run` 클립을 연결했다. 실제 수평 이동 속도에 따라 대기·걷기·달리기를 0.18초로 전환하며, 벽에 막혀 이동하지 않으면 달리기를 멈춘다. 달리기 중 카메라 거리·시야각을 확대하지 않는다.

구현: [입력](../../shared/src/input.ts), [이동 속도](../../apps/spike-playcanvas/src/main.ts), [애니메이션·안내](../../apps/spike-playcanvas/src/character.ts).

## 확인 결과

별도 headed Chromium, 시험 탭 1개, Apple M4 Pro / ANGLE Metal, DPR 1. 개발 서버 5174의 기능 확인이며 아래 속도는 각 시점의 앱 진단 표본이다. 성능 비교나 장시간 안정성 판정이 아니다.

| 시험 | 관찰 |
|---|---|
| 1440×900, W → Shift+W → W → 해제 | Walking 1.95 → Running 3.40 → Walking 1.84 → Idle, 거의 0 단위/초 |
| 오른쪽 Shift만 누름 | Idle, 이동하지 않음 |
| 오른쪽 Shift+W, 시험 통로 끝까지 약 4초 | Running에서 벽 앞 z≈−6.65에 정지, 입력을 유지해도 Idle·속도≈0. 카메라 hold 유지 |
| 달리는 중 합성 blur | 입력 초기화 후 Idle·속도 0 |
| 390×844, 왼쪽 합성 터치 거리 50 → 90 → 75 → 60 px → 해제 | Walking → Running → Running → Walking → Idle. 속도 약 1.80 → 3.31 → 3.40 → 1.89 → 0 |
| 안내 패널 | 390×844·844×390에서 페이지 크기가 viewport를 넘지 않음. 가로 화면의 긴 안내는 패널 내부 스크롤. 닫으면 안내·조작 버튼 하나만 남음 |

스크린샷에서 전신 달리기와 모바일 안내 줄바꿈을 확인했다. 모바일 입력은 데스크톱 Chromium의 합성 TouchEvent이며 iPhone 실기기·손가락 사용성 확인을 대신하지 않는다. 콘솔 오류는 favicon 404뿐이었다. `pnpm check`의 기존 시험·타입 검사·두 앱 빌드·자산 검증 통과. 번들 크기 경고는 남아 있다.

## 인물과 맵 크기: 실제 비율까지 맞춘 상태는 아님

인물은 초기 메시 경계 높이를 월드의 `capsuleHeight: 1.7`에 맞춰 정규화한다. `sunnyvale-content.json`은 미터 단위를 선언하고 장면·충돌 메시의 배율을 `[1,1,1]`로 사용한다. 그러나 미터 선언은 실측 검증의 근거가 아니다. [SECOND-SCENE.md](../implementation/SECOND-SCENE.md)는 원본 예제의 단위를 따랐으며 **실측 축척을 검증하지 않았다**고 명시한다. 현재 인물을 실제 장소와 정확한 1.7m 비율로 맞췄다고 말할 수 없다.

화면에서도 인물이 작게 느껴질 수 있다. 현재 카메라 거리 3.8 단위·수직 시야각 70°이며, 데스크톱 달리기 화면에서 전신이 화면 높이의 약 30%를 차지한다. 넓은 시야가 이 인상에 기여할 수 있다는 해석이며, 이것만으로 맵이 실제보다 몇 배 크다고 판단하지 않는다.

이번에는 인물·충돌체·맵 크기를 변경하지 않았다. 다음 크기 조정은 두 목적을 구분한다. 화면에서 인물을 더 크게 보고 싶다면 카메라 거리를 먼저 조정한다. 실제 장소 대비 비율을 맞추려면 치수를 아는 물체나 현장 실측을 기준으로 스플랫·충돌체·이동 단위의 관계를 함께 검증한다. 인물 메시만 키워 이를 실측 보정이라고 표현하지 않는다.
