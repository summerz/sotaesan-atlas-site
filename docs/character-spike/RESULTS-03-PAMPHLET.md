# 3회차: 책상에서 안내문 전달·읽기

- 작성일: 2026-11-07
- 구성: PlayCanvas + Ammo, `sunnyvale-content`, 기존 CC0 방문자·교무님 역할 NPC.
- 실행: `http://127.0.0.1:5174/?scene=content&character=1`

## 구현한 흐름

1. NPC 옆에 나무 책상과 안내문 묶음을 둔다. 책상은 충돌 박스를 포함한 기본 도형이며 신규 외부 자산은 없다.
2. 방향 제한 없이 거리 3.5 단위 안에서 `E · 인사 후 안내문 받기` 버튼 또는 E로 시작한다. 방문자는 제자리에서 실제 합장·15도 허리 인사를 한다. 허리를 펴고 손까지 내린 뒤 NPC·책상을 피해 앞쪽 받는 자리로 자동으로 걷는다. 이동 중 버튼도 사용할 수 있다.
3. 자동 이동이 끝난 뒤 약 3.4초 동안 NPC가 책상에서 집어 들어 방문자에게 건넨다. 자동 이동과 전달 중에는 사용자 이동·카메라 조작·합장·중복 받기를 막는다. 전달 시작 후 2.7초에 소지 상태를 확정하고 동작이 끝나면 ‘안내문 열기’ 버튼을 표시한다.
4. 버튼으로 화면 위에 떠 있는 안내문 창을 연다. 사방 여백을 최소 16px 남기고 데스크톱 최대 크기를 1100×860px로 제한한다. 닫기·Escape로 장면으로 돌아가며 다시 열 수 있다. 읽는 동안 이동·R 복귀 입력이 장면에 전달되지 않는다. 닫은 직후 첫 이동 입력도 받도록 키 처리 전에 차단 상태를 갱신한다.
5. 포커스 이탈·페이지 숨김 시 전달을 중단한다. 수령 확정 전이면 다시 받을 수 있고, 확정 후면 소지를 유지한다. R·새로고침은 소지를 초기화한다. 영구 보관이나 네트워크 동기화는 없다.

화면 문안은 조작을 설명하는 **시험용 안내**다. 실제 성지·교리의 승인된 해설을 넣지 않았다. 읽기에는 native `dialog`, 제목 연결, 닫기 포커스, 키보드 복귀, 작은 화면의 내부 스크롤을 사용했다. 아래 이전 검증의 ‘전체 화면’과 0.85 거리 제한은 이번 보완 전의 기록이다.

## 사용자 피드백: 받기 버튼에서 실제 인사 후 접근

이전에는 ‘인사 후 안내문 받기’가 비활성 버튼의 설명이어서 눌러도 인사를 하지 않았다. 이제 시작점처럼 약 3.35 단위 떨어진 곳에서도 누를 수 있도록 요청 범위를 3.5로 확대했다. 요청하면 방문자 합장 인사를 시작하고, NPC도 인사 중이 아니면 인사한다. 이미 진행 중인 인사는 방향을 유지하며 마친다. 양쪽 인사가 끝난 뒤 자동 접근하고 마지막으로 전달한다. 인사 중에는 이동·중복 요청을 막고 종이를 상판에 유지하며, 접근 시간과 전달 시간도 진행하지 않는다. 포커스 이탈·초기화 시 대기 중인 인사 요청도 취소한다.

headed Chrome 단일 탭에서 **10개 확인 통과**: 기존 2.6보다 먼 시작 거리에서 버튼 활성화, 실제 15도 허리·합장 자세, 인사 중 수평 위치 유지, 접근·전달 선행 없음, 허리를 편 뒤 손 내림, 인사 완료 후 보행, 수령 완료, 인사 중 취소와 E 재시도. [상태 원본](evidence/2026-11-07/guide-greeting/review.json) · [합장 화면](evidence/2026-11-07/guide-greeting/bow.png). 초기 지면 정착에 따른 Y 변화는 제자리 수평 이동 판정에서 제외했다. PlayCanvas 단위 검사 **27개**, 전체 워크스페이스 타입 검사·프로덕션 빌드 통과. 아래 2.6 범위 검증은 이번 수정 전의 기록이다.

## 사용자 피드백: 접근·방향·안내문 창 보완

- NPC는 자동 인사 시작 시 방문자를 향한 회전을 한 번 정하고 인사가 끝날 때까지 유지한다. 이동하는 방문자를 따라 허리를 돌리지 않는다. 수용된 합장·15도 허리 인사 순서는 그대로 유지한다.
- 받기 범위는 0.85 → 2.6으로 확대하고 정면 조건을 없앴다. 자동 접근은 최대 1.6 단위/초의 강체 속도를 사용한다. NPC 주변 반경 1.6의 경유점을 따라 안내대를 피해 이동한 뒤 앞쪽 0.82 자리에서 전달한다. 접근 중에는 전달 시계를 진행하지 않는다. 12초 안에 도착하지 못하면 중단 안내를 표시하고 재시도를 허용한다. 일반 길찾기나 전체 지형 통과를 보장하는 구현은 아니다.
- 종이 중심과 집는 손 목표의 가로 좌표를 안내대 기준 0.29 → 0.43으로 함께 이동했다. 종이 가로 범위는 0.335–0.525, 상판 범위는 0.32–0.88로 전체가 상판 안에 들어간다. 세로 범위도 종이 0.275–0.525, 상판 0.16–0.64로 안쪽이다.
- 사용자에게 보이는 명칭과 현행 캐릭터 실험 문서는 ‘안내문’으로 통일했다. 기존 영문 코드·파일명과 보존된 과거 검증 JSON은 추적을 위해 유지한다.
- PlayCanvas 소리는 자산 로딩 전부터 마스터 볼륨 0으로 시작하고 버튼도 ‘소리 켜기’로 맞췄다. 사용자가 직접 켤 수 있다.
- 카메라의 장애물 투영 결과를 한 프레임에 적용하던 처리를 바꿨다. 이동을 초당 5 단위로 제한하고 이동 경로를 다시 검사하며 바라보는 회전도 보간한다. 갑작스러운 시야 가림은 즉시 캐릭터까지 당겨 해결하지 않으므로, 모서리에서는 잠시 인물이 가려지거나 카메라가 벽 앞에 남을 수 있다. 사용자가 신고한 정확한 좌표는 확보하지 못했으므로 해당 지점 해결을 단정하지 않는다.

검증: headed Chrome 1개 탭에서 **12개 확인 통과**. 약 1.95 거리에서 받기, 접근 후 전달 시계 시작, 왼쪽·뒤쪽·안내대 쪽 세 경로의 수령, 인사 도중 방향 고정, 음소거 초기값, 1200×919 / 390×844 / 320×568 / 844×390의 창 여백·넘침 없음, Escape 닫기를 확인했다. 모바일 크기 검증이며 iPhone 실기기 검증은 아니다.

- 소리 켜기·끄기, 접근 도중 포커스 이탈로 중단, 재시도, 읽는 중 이동·R 차단도 **5개 확인 통과**. [중단·입력 원본](evidence/2026-11-07/guide-review/interruption.json). 이 원본의 카메라 속도는 비동기 타이머 표본 사이의 값으로, 프레임별 속도 제한의 측정값으로 사용하지 않는다. 이동 경로에서는 `follow` 모드만 관측해 신고된 장애물 지점을 재현하지 못했다.

## 이전 보완: 손목·종이 부착점 (아래 자세 우선 방식으로 대체)

- 손목을 인물 기준 수평 회전으로 고정하던 계산이 옆·아래로 뻗는 팔과 충돌했다. 손가락 방향을 팔뚝 방향에 맞추고 대기 애니메이션의 손가락 굽힘을 제거했다.
- 종이를 손목 좌표에 놓으면 종이 몸통이 손바닥과 팔에 겹쳤다. **엄지·검지 사이를 잡는 위치로 삼고 종이 몸통을 손끝 바깥으로 배치**했다. 엄지는 검지 쪽으로 모으며, 수령자의 손으로 부착점을 넘긴다.
- 팔 길이 안에서 닿도록 책상 높이·집는 모서리·수령 거리를 맞췄다. 관절 보정은 렌더 직전에 적용하고 직후 복원해 대기 자세에 누적하지 않는다.
- 집기·들어 올리기·전달의 확대 화면을 확인했다. 확대 검토 화면은 시험 도구가 잠시 카메라 위치와 시간을 바꿔 촬영한 것으로, 기본 사용자 시점과 구분한다.

## 사용자 피드백: 자세를 먼저 정하고 배치를 맞추기

기존 방식은 접근한 두 인물의 중간점에 손을 맞추려 해서 팔이 벌어지고 비틀리는 문제가 남았다. 이번에는 **팔꿈치를 몸 가까이 아래로 두고, 팔뚝을 앞으로 내미는 짧은 전달 자세**를 먼저 정했다.

- NPC 기준 집기 손목 `(0.29, 1.28, 0.18)`, 전달 손목 `(0.18, 1.28, 0.24)`를 사용한다. 장면 임의의 중간점으로 팔을 늘리지 않는다. 손바닥은 수평으로 유지한다.
- 이 자세에 맞춰 옆 책상을 좁은 안내대로 바꾸고, 상판 높이·안내문 묶음 위치·충돌 박스를 함께 옮겼다. NPC·책상·전달 자세는 공통 방향(-45도)을 사용한다.
- 앞쪽에서만 받을 수 있다. E를 누르면 첫 0.4초 동안 방문자의 X/Z를 NPC 앞 0.82 단위 위치로 부드럽게 맞춘 뒤 팔을 든다. 높이는 기존 캡슐·바닥 물리가 유지한다. 옆·뒤에서는 앞쪽으로 오라는 안내를 표시한다.
- 종이는 엄지·검지 사이에서 손끝 바깥으로 유지하며 수령자에게 넘긴다. 서로 반대인 손 회전을 보간해 종이가 중간에 세워지던 문제도 제거했다.
- W를 놓을 때 돌아서는 문제는 Euler 각의 Y값만 읽던 데서 발생했다. 180도 방향이 X/Z 회전으로 분해될 때 Y가 0이 되는 경우를 피하도록 실제 회전의 전방 벡터에서 수평 방향을 구한다. 합장·수령 후에 정한 방향도 보존한다.

현재 화면은 [기본 시점 집기](evidence/2026-11-07/pamphlet/natural-pose/natural-pose-pickup.png), [기본 시점 전달](evidence/2026-11-07/pamphlet/natural-pose/natural-pose-offer.png), [집기 확대](evidence/2026-11-07/pamphlet/natural-pose/natural-pose-pickup-close.png), [전달 확대](evidence/2026-11-07/pamphlet/natural-pose/natural-pose-offer-close.png)로 기록했다. 확대 화면은 도구가 카메라·시간을 일시 조정한 검토용이다.

이번 수정에서 다시 확인한 결과:

- W/S/A/D/W+A/W+D 여섯 방향 모두 이동 후 정지 방향 유지. 정지 전후 각도 차이는 최대 약 0.14도. [실제 아바타 방향·좌표 원본](evidence/2026-11-07/pamphlet/natural-pose/facing-regression.json).
- 안내문 수령·이동 차단·전체 화면·모바일 크기·중단·재시도 등 기존 13개 확인 모두 통과. [원본](evidence/2026-11-07/pamphlet/natural-pose/natural-pose-regression.json).
- 기존 합장·이동 취소·재접근·모바일 버튼 등 9개 확인 모두 통과. [원본](evidence/2026-11-07/pamphlet/natural-pose/natural-pose-greeting-regression.json).
- PlayCanvas 단위 검사 26개, 타입 검사·프로덕션 빌드 통과. 기존 worker 외부화·큰 번들 경고 유지. 성능 측정은 하지 않았다.

## 이전 보완 검증과 범위

- PlayCanvas 단위 검사 **26개 통과**, 타입 검사·프로덕션 빌드 통과. 빌드는 엔진 worker의 Node 모듈 외부화·큰 번들 경고를 표시한다.
- headed Chrome, 데스크톱 1200×919와 모바일 크기 390×844에서 안내문 흐름 **13개 확인 통과**: 거리 제한, 시작 가능, 전달 시작, 전달 중 이동 차단, 수령 완료, 읽기 중 이동 차단, 전체 화면 크기, 닫기, 작은 화면 넘침 없음, 이동 재개, R 초기화, 중단, 재시도. [상태 원본](evidence/2026-11-07/pamphlet/pamphlet-regression.json).
- 기존 접근 인사·답례·반복 방지·이동 취소·재접근·모바일 버튼 흐름 **9개 확인 통과**. [원본](evidence/2026-11-07/pamphlet/greeting-regression.json).
- 실제 렌더 프레임에서 손 방향을 확인했다. 집기 완료 구간에서 손가락 축과 팔뚝 축의 각도는 약 0도였다. 이 수치는 손목 꺾임 확인이며, 손가락·종이의 정밀 접촉이나 자연스러움에 대한 합격 판정은 아니다. [원본](evidence/2026-11-07/pamphlet/pamphlet-hand-review.json).
- 콘솔 오류는 기존 `favicon.ico` 404 한 건이며, 이번 흐름에서 새 실행 오류는 확인하지 않았다.
- 모바일은 데스크톱 viewport 변경·버튼 입력 확인이다. 실제 iPhone Safari의 성능·손가락 조작 검증으로 간주하지 않는다. 성능 비교는 실시하지 않았다.

관절과 종이의 접촉은 절차적 보정이며 물리적인 집기나 전용 모션 캡처가 아니다. 새 방식은 받는 방향과 위치를 제한한다. 손가락의 정밀한 종이 접촉, 교무님 전용 외형, 정식 안내문 문안은 남아 있다. 사용자에게 손 모양의 최종 승인을 받은 상태는 아니다.
