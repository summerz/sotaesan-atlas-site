원거리 저해상도 표현과 근거리 교체

2026-10-03. 공간 분할 시험에 먼 구역의 저해상도 표현을 추가했다. Three.js와 PlayCanvas에 같은 자산·선택 정책을 적용했다. 데스크톱에서 로딩 지연·실패 중에도 해당 구역의 표현이 유지되고, 정밀 자산이 준비되면 교체되는 것을 확인했다. 교체 순간 선명도가 달라지는 현상은 남아 있다. 화면 품질 전체나 엔진 우열을 통과 판정한 결과는 아니다.

자산과 재현

900,000점 Hall 마스터를 기존 정밀 자산과 같은 다섯 X 구역으로 나눴다. scripts/make-spatial-lod.py가 구역별로 splat-transform 3.7.0 --gpu cpu --filter-harmonics 0 --decimate-adaptive 10%를 적용하고 SOG로 인코딩한다. 원본의 일부 점을 무작위로 고르는 대신 적응형 축소를 사용한다. 두 표현의 위치·회전·스케일과 구역 범위는 일치한다. 점 수·크기·해시는 저해상도 메타데이터에 기록한다.

표시·로딩 정책

  • 저해상도 다섯 구역을 먼저 순차 준비하고 계속 상주시킨다. 그다음 시작점 주변의 정밀 구역을 준비한다.
  • 정밀 구역이 준비되기 전에는 그 구역의 저해상도만 표시한다. 준비되면 같은 프레임의 상태 변경에서 저해상도를 숨기고 정밀 자산을 표시한다. 해제 때는 반대로 처리한다.
  • 두 표현의 알파를 동시에 섞는 페이드는 사용하지 않는다. 구역별 표시 상태가 겹치지 않게 하지만 선명도 변화가 눈에 띌 수 있다. Gaussian 타원체가 구역 경계를 넘는 문제는 별도로 남는다.
  • 정밀 자산의 로딩 지연·실패 중에는 저해상도가 유지된다. 저해상도 표시만으로 이동이나 콘텐츠 소유권을 허용하지 않는다. 필요한 정밀 구역이 준비되지 않으면 경계에서 이동을 기다린다.
  • 정밀 로딩 실패는 자동 반복 요청하지 않는다. 구역 로딩 재시도로 복구한다. 최초 저해상도 준비 실패는 오류와 다시 시도를 표시하며 부분 준비 자산을 정리한다.
  • 공통 충돌 메시 24삼각형은 계속 유지한다. 복잡한 충돌 메시의 구역별 교체를 검증한 것은 아니다.
