## 1. 이 단계의 정의

**콘텐츠 스파이크**: 대역 공개 장면 위에서 네 가지 표현 수단의 실현 가능성, 비용, 데스크톱 기기 예산, 데이터 계약을 확인하는 기술 시험. 모바일은 참고 측정이며 판정에 쓰지 않는다(2026-10-14 사용자 결정: 모바일이 주요 기기가 아닐 가능성이 높아졌고, 시험 기기는 출시 7년 된 iPhone 11이다). 십상 이해나 학습 효과를 검증하는 단계가 아니다. 그 평가는 실제 성지 데이터와 검수된 콘텐츠가 준비된 다음 단계에서 과제·비교 조건·표본을 다시 설계한다. [01-codex-critique.md](01-codex-critique.md) 질문 5의 평가 설계를 출발점으로 쓰되, 거기 적힌 8명을 확정 기준으로 승계하지 않는다.

## 2. 전제

- **대역**: `sunnyvale-era` 변형 한 가지. 원본 `sunnyvale.sog` 해시(SHA-256 `604ede4a…`)는 출처 식별용이다. 실행에 사용하는 `sunnyvale-era`의 분할·LOD·충돌 및 추가 자산 해시와 빌드 식별자를 함께 고정한다.
- **하늘 축의 대역을 Sunnyvale로 두는 근거**: 원본 iPhone 캡처([ios-playcanvas-sunnyvale.png](../implementation/measurements/2026-10-02/ios-playcanvas-sunnyvale.png))와 `sunnyvale-era` 데스크톱 캡처에 하늘 표현이 보이고, 앱에 별도 하늘 배경 설정이 없다. 제거 가능한 점 집합과 경계 보존은 미확인이며 이 시험에서 확인한다. Knock Hall 축소본은 하늘이 검게 비어 있어 하늘 축 대역이 될 수 없다.
- **두 번째 장면**: 기존 Knock Hall 변형. 실내이므로 하늘 분리의 이전은 검증하지 못하며 그렇게 기록한다.
- **엔진**: PlayCanvas + Ammo 한 구성. iPhone 결과를 제외해도 기존 데스크톱 로딩(cold 중앙값 Ammo 1,560ms 대 BVH 2,784ms, Rapier 3,009ms)과 프레임 간격 관찰(Sunnyvale 원본 p95 Ammo 33.8ms 대 BVH 50.5ms)은 PlayCanvas + Ammo를 우선 후보로 유지할 근거가 된다. 이번 스파이크는 이 한 구성으로 진행하며 최종 엔진 확정은 아니다. 계약과 자산의 엔진 중립 설계는 유지하되 엔진별 실행 코드의 무수정 이전을 보장하지 않는다.
- **콘텐츠 데이터**: 실제 십상 사실이 아니라 **임시 문장**을 쓴다(2026-10-16 사용자 결정). 임시 대본은 하나의 흐름을 보여주도록 짠다. 예: 진입 지점의 안내문 → 정지 지점 2–3곳의 설명문(각각 `representation`과 `confidence` 값이 다른 것으로 구성) → 임시 출처 항목 → 시대 전환 전후의 설명 변경. 목적은 텍스트·음성·자막·출처·표현 구분이 같은 내용을 전달하는지 확인하는 것이며, 문장의 사실성은 검증 대상이 아니다. 실제 출처와의 연결 확인은 이 단계에서 빠진다. 화면에 "기술 시험용 대역 · 임시 문장" 표시를 상시 띄운다. `sunnyvale-era`의 과거는 실제 역사 복원이 아니다.
- **제외**: 안개·강수·주야간, 동행 캐릭터·길 찾기·대화, 타임랩스, 과거 창 셰이더, 다중 컷 연출, 초심자 평가, 새 촬영, 새 공개 장면 탐색(하늘 축 실패 시에만 상한 내 조사).

**총계: 정지 인물 기준 10–18.5인일 (추정). 왕복 포함 11–20.5. 새 공개 장면이 필요해지면 +3.5–7.** v1 대비 절감은 두 가지다. iPhone 구성 시험 18회를 2회로 줄이고 모바일 실패 주입을 삭제해 0.5인일, 실제 사실 조사와 교무 검수를 임시 문장으로 대체해 0.5–1인일. 횟수와 비용은 비례하지 않는다.

예산 조건:

- 1인일은 8시간 실작업. 승인·섭외·기계 처리 대기는 별도. 실측 견적이 아니라 첫 회차 기록으로 갱신할 계획 범위다.
- 이용 조건이 확인된 간단한 음원·인물 자산을 전제로 하며 새 고품질 모델 제작은 제외한다. 사실 자료와 검수자는 임시 문장 사용으로 이 단계에서 필요 없다.
- 축별 비용은 구현·단독 시험, 공통비는 횡단 작업으로 중복 계산하지 않는다.
- 새 장면 +3.5–7인일은 조사 0.5–1과 정합·충돌·기준 시험 3–6이며 복잡한 하늘 제거 비용은 제외한다. 상한을 승인받지 못하면 해당 축을 보류한다.
- 촬영 제약 전달은 이번 범위지만 후속 촬영 체크리스트 협의 0.5–1인일은 별도다.

## 5. 성능 합격선 (잠정, 측정 전 확정)

- 데스크톱(하드웨어 GPU 확인, headed, 고정 빌드·자산·viewport·DPR·캐시 조건) 활성 탐색의 전체 프레임 간격 **p95 ≤ 40ms** 및 동일 조건 기준 실행 대비 증가 **≤ 5ms**를 모두 만족해야 한다. 3회 각각 판정하며 한도는 정식 시험 전에 고정한다. 기준 실행(모두 off)도 절대선의 적용 대상이며, off부터 40ms를 넘으면 기준 구성 미달이다. 측정 후 절대선을 기준 실행 값으로 완화하지 않는다.
- 로딩, 레일 재생, 수동 탐색 통계를 분리.
- 40ms는 기존 Sunnyvale 원본 데스크톱 측정(Ammo p95 33.5–34.3ms)에 축 예산 5ms를 더해 참고한 제안값이며 검증된 사용성 기준이 아니다. 5ms 증가 한도는 기존에 on/off 비교가 없어 충족 여부가 미검증이다. 받아들이지 않으면 대체 한도를 측정 전에 정한다. JS heap만으로 전체 메모리 안전성을 판정하지 않는다.
- iPhone에는 합격선을 적용하지 않는다. iPhone 11 참고 측정은 모바일 일반의 성능이나 사용성을 대표하지 않는다. 1회 측정은 재현성을 보장하지 않는다.

## 6. 중단·전달 규칙

- 성능·실패 주입 시험의 판정 대상은 데스크톱이다. 어느 축이든 데스크톱 합격선을 넘지 못하면 그 축은 보류하고 다른 축을 계속한다. 레일 실패 후 트리거+자막은 "실패 후 대체"로 기록하며 레일 축 통과가 아니다. 하늘 품질·바닥 정합 같은 비기기 합격선은 그대로 유효하다.
- iPhone 참고 결과는 축 통과·보류, 최종 추천, 완료 여부를 바꾸지 않는다. 열리지 않으면 "실패한 구성, 원인 미분리"로 관찰 사실만 기록하며 축별 원인으로 단정하지 않는다.
- 어느 축이든 촬영 전제(하늘 포함 여부, 인물 배치 공간, 연출 동선, 스카이박스용 하늘 자료)를 바꾸면 즉시 촬영 계획 체크리스트에 전달한다. 두 번째 실패를 기다리지 않는다.
- 두 번째 장면 이전에서 콘텐츠별 앱 코드 수정이 필요하면 "선언형" 주장을 철회하고 수정 범위를 기록한다.
- 하늘 교체가 성공해도 "실제 촬영 때 하늘을 빼도 된다"는 결론은 내리지 않는다. 촬영·재구성 조건은 이 저장소가 시험하지 않았다.
