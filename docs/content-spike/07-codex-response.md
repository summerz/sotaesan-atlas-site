## 1. 06의 질문 다섯 개에 대한 답

### 1) 재작성인가, 수정인가

**수정이 맞다.** 독립적으로 검토해도 판정 기기와 검증 범위의 변경이지 네 축의 목적·대역·계약·재사용/재저작 구분의 변경은 아니다. 사용자 결정은 제품 방향으로 반영한다. 기존의 “iPhone 실패가 축 보류를 일으킬 수 있다”는 결론은 철회하고, 모바일 관찰을 축 판정·최종 추천·완료 조건에서 제외한다.

Claude와 **엔진 근거 해석은 다르다.** 모바일을 제외해도 PlayCanvas 우선 후보 추천은 유지된다(질문 4). “근거가 크게 약해져 재검토가 필요하다”는 결론은 승계하지 않지만 전면 재작성 사유는 아니다.

### 2) 데스크톱 33ms / 증가 5ms는 양립하는가

**33ms를 기존 측정이 뒷받침하지는 않는다.** [보행 비용 비교의 전체 프레임 표](../implementation/PHYSICS-COST-COMPARISON.md)는 다음과 같다. 단위는 ms, 각 값은 30초 실행별 p95의 3회 중앙값이다.

| 구성 | 시작점 정지 | 외벽 밀기 |
|---|---:|---:|
| Three.js BVH | 50.5 | 49.3 |
| Three.js Rapier | 50.3 | 116.7 |
| PlayCanvas Ammo | 33.8 | 33.7 |

[원본 JSON](../implementation/measurements/2026-10-02/physics-browser.json)의 Ammo 반복값도 정지 33.8/33.8/33.6, 외벽 33.7/33.5/34.3으로 모두 33을 초과한다. M4 Pro·headed Chromium 154·하드웨어 GPU, 1200×863 CSS px·기기 DPR 2·앱 상한 1.5 조건이다. 원본 Sunnyvale 측정이므로 이번 `sunnyvale-era`의 33ms 달성 불가능을 뜻하지는 않는다.

**대안은 p95 ≤ 40ms AND 증가 ≤ 5ms**다. 40은 관찰 최대 34.3 + 추가 예산 5 = 39.3을 참고한 **제안값**이지 검증된 사용성 기준이 아니다. 5ms는 유지하되 기존에 네 축 on/off 비교가 없어 충족 여부는 미검증이다. [로딩·메모리 비교](../implementation/LOADING-MEMORY-COMPARISON.md)의 준비 시간·heap도 이를 입증하지 않는다.

동일 조건의 off/on 대응 실행을 3회 각각 판정하고 로딩·레일·수동 탐색 통계를 분리한다. off부터 40을 넘으면 기준 구성 미달이다. **측정 후 절대선을 off 값으로 올리거나 증가량만 남기는 예외는 삭제**해 [FINAL-v1 §3·§5](FINAL-v1.md)의 사전 고정 원칙을 지킨다.

### 3) iPhone 두 구성 × 1회면 충분한가

**참고 관찰로 충분하다.** 구성 시험 18회 → 2회, 모바일 실패 주입 7종 × 3회도 삭제된다. off/on 각 1회 열림 여부와 가능한 프레임 p95·heap을 기록한다. on 실행 안에서 재생 거부, 레일 재생·건너뛰기를 각 한 번 확인하되 탐색 통계와 분리한다. 별도 반복·손가락 시험은 하지 않는다.

1회 p95는 재현성 보장이 아니다. bridge로 얻지 못한 heap은 미측정으로 남긴다. 접속·로딩 실패도 기록하고 모바일 전용 조사·수정·재시험을 완료 조건으로 삼지 않는다. **모두 on 실패로 축을 특정할 수 없으므로 “실패한 구성, 원인 미분리”라고 쓴다.** 축 판정·최종 결론은 바꾸지 않는다.

### 4) 모바일을 빼면 엔진 추천이 유지되는가

**유지된다. 이번 스파이크에 Three.js 병행은 필요 없다.** [결정 보고서 §1·§3·§4](../implementation/SPIKE-DECISION-REPORT.md)는 데스크톱 준비 시간도 추천 근거로 명시했다. “주로 iPhone”, “데스크톱 로딩 차이는 작았다”는 06의 요약은 부정확하다.

- cold 중앙값: Ammo **1,559.9ms**, BVH 2,784.2ms, Rapier 3,008.5ms. Ammo가 각각 약 **44%, 48%** 짧다. 3회 범위도 Ammo 1,497.2–1,569.5ms와 BVH 2,600.6–2,888.4ms, Rapier 2,883.5–3,235.3ms가 겹치지 않는다.
- warm 중앙값: Ammo **766.9ms**, BVH 1,742.0ms, Rapier 2,021.4ms. 질문 2의 전체 프레임 결과도 이 조건에서는 Ammo 쪽이 더 일정했다.

로컬 앱 준비 표시이지 GPU 첫 표시·배포 성능은 아니며, 프레임 시험의 접촉 위치·작업량도 다르다. 메인/worker heap·backing storage로 전체 RAM 우열도 판단할 수 없다. **현재 구현의 우선 후보**이지 최종 확정은 아니다. 다음 단계의 선택 여지는 남기되 모바일 축소만으로 재비교를 의무화하지 않는다.

### 5) 인일 조정은 타당한가

**계획 추정으로 수용한다.** 검증 2–3 → 1.5–2.5인일, 총계 **10.5–19.5**, 왕복 포함 **11.5–21.5**는 맞다. 네 축 6–11과 나머지 공통 작업 3–6은 유지된다. 실측 견적이 아니므로 “비용의 약 절반이 iPhone”은 삭제한다. 횟수와 준비·계측·분석 비용은 비례하지 않는다.

기존 bridge 재사용, 모바일 전용 수정·재시험 제외를 전제로 한 **0.5인일 절감 추정**이다. 기존 예산 조건과 첫 회차 작업시간 기록 원칙을 유지한다. 새 장면 +3.5–7, 별도 촬영 협의 0.5–1은 변경하지 않는다.

## 2. 06 §3 수정 문안별 판정

아래 인용문은 교체·추가할 문안이다. 별도 언급하지 않은 합의 내용은 유지한다.

1. **§1 정의 — 동의.** “데스크톱 기기 예산”으로 바꾸고 사용자 결정 날짜와 모바일 비판정 원칙을 추가한다.
2. **§3 듣기 — 동의.** 판정 기기를 데스크톱 브라우저로 바꾼다. 기존 재생 조작·거부/음원 실패·음소거·복귀와 자막 대체 기준은 유지한다. iPhone 거부 확인은 질문 3의 단일 on 실행 안에 포함한다.
3. **§3 연출 — 동의.** 실패 주입 7종의 목록·복구 기준은 그대로 두고 데스크톱 각 3회만 판정한다. iPhone 레일 재생·건너뛰기는 참고 기록이다.
4. **§4 결합·기기·실패 검증 — 수정.** 제안한 횟수·인일에 다음을 추가한다: “데스크톱 실행 순서 교차와 동일 경로·빌드·자산·viewport·캐시 조건을 유지한다. iPhone 수집 불가 항목은 미측정으로 남기며 모바일 전용 원인 조사·수정·재시험은 이번 범위에서 제외한다.” 같은 비용이 적힌 **FINAL §8 실행 순서 4번도 1.5–2.5인일로 맞춘다.**
5. **§5 성능 합격선 — 수정.** “데스크톱 활성 탐색 전체 프레임 간격 p95 ≤ 40ms 및 동일 조건 기준 실행 대비 증가 ≤ 5ms를 모두 만족해야 한다. 3회 각각 판정하며 한도는 정식 시험 전에 고정한다. 기준 실행도 절대선의 적용 대상이다. iPhone에는 합격선을 적용하지 않는다.” 기존 기기·통계 분리 조건은 유지하고 기준값 자동 대체 문장은 삭제한다.
6. **§6 중단 규칙 — 수정.** “성능·기기별 실패 시험의 판정 대상은 데스크톱이다. iPhone 참고 결과는 축 통과·보류, 최종 추천, 완료 여부를 바꾸지 않는다. 열리지 않으면 실패한 구성과 관찰 사실만 기록하며 축별 원인으로 단정하지 않는다.” 하늘 품질 등 비기기 합격선은 그대로 유효하다.
7. **§7 — 수정.** 제안 문장에는 동의하지만 대상 문장은 실제로 **FINAL §5 마지막 항목**에 있다. 그곳을 “iPhone 11 참고 측정은 모바일 일반의 성능이나 사용성을 대표하지 않는다”로 교체한다. §7의 재사용/재저작 표는 변경하지 않는다.
8. **§2 엔진 전제 — 수정.** “iPhone 결과를 제외해도 기존 데스크톱 로딩·프레임 관찰은 PlayCanvas + Ammo를 우선 후보로 유지할 근거가 된다. 이번 스파이크는 이 한 구성으로 진행하며 최종 엔진 확정은 아니다. 계약과 자산의 엔진 중립 설계는 유지하되 엔진별 실행 코드의 무수정 이전을 보장하지 않는다.”

결론: **전면 재작성 없이 수정한다.** 모바일 비판정·축소 범위와 비용에는 합의하며, 33ms 자동 완화와 엔진 추천 근거의 축소 해석은 위 문안으로 바로잡는다.
