## 1. 이 단계의 정의

**콘텐츠 스파이크**: 대역 공개 장면 위에서 네 가지 표현 수단의 실현 가능성, 비용, 기기 예산, 데이터 계약을 확인하는 기술 시험. 십상 이해나 학습 효과를 검증하는 단계가 아니다. 그 평가는 실제 성지 데이터와 검수된 콘텐츠가 준비된 다음 단계에서 설계한다(Codex 1라운드 질문 5의 평가 설계를 그때 출발점으로 쓴다).

## 2. 전제

- 대역: `sunnyvale-era` 변형 한 가지, 자산 해시 고정 (`sunnyvale.sog` SHA-256 `604ede4a…`). 하늘 축을 위해 Sunnyvale을 쓰는 이유는 원본 캡처에 하늘 표현이 있기 때문이다. 제거 가능 여부는 이 시험에서 확인한다.
- 두 번째 장면: 기존 Knock Hall 변형. 실내이므로 하늘 분리의 이전은 검증하지 못하며 그렇게 기록한다.
- 엔진: PlayCanvas + Ammo 한 구성. 스파이크 보고서의 우선 후보를 일정 가정으로 쓴 것이며 최종 선택이 아니다.
- 콘텐츠 데이터: 실제 십상 사실 3개와 출처를 대본으로 준비해 얹는다. 학습 증명이 아니라 텍스트·음성·자막·출처·표현 구분이 같은 내용을 전달하는지 확인하는 시험 데이터다. 화면에 "기술 시험용 대역" 표시를 상시 띄운다.
- 제외: 안개·강수·주야간, 동행 캐릭터·길 찾기·대화, 타임랩스, 과거 창 셰이더, 다중 컷 연출, 초심자 평가, 새 촬영, 새 공개 장면 탐색(하늘 축 실패 시에만 상한 내 조사).

**총계: 정지 인물 기준 11–20인일 (추정). 왕복 포함 12–22. 새 공개 장면이 필요해지면 +3.5–7.** 1인일은 8시간 실작업이며 승인·섭외·기계 처리 대기는 별도. 실측 견적이 아니라 첫 회차 기록으로 갱신할 계획 범위다.

## 5. 성능 합격선 (잠정, 측정 전 확정)

- 활성 탐색의 전체 프레임 간격 p95 ≤ 50ms (iPhone, 고정 빌드·자산·viewport·캐시 조건).
- 동일 조건의 기준 실행 대비 증가 ≤ 5ms.
- 로딩, 레일 재생, 수동 탐색 통계를 분리. 3회 각각 판정.
- 이 숫자는 Codex 제안이며 기존 장면이 충족했다는 진술이 아니다. 받아들이지 않으면 대체 한도를 측정 전에 정한다. JS heap만으로 전체 메모리 안전성을 판정하지 않는다.

## 6. 중단·전달 규칙

- 어느 축이든 합격선을 넘지 못하면 그 축은 보류하고 다른 축을 계속한다. 레일 실패 후 트리거+자막은 "실패 후 대체"로 기록하며 레일 축 통과가 아니다.
- 어느 축이든 촬영 전제(하늘 포함 여부, 인물 배치 공간, 연출 동선, 스카이박스용 하늘 자료)를 바꾸면 즉시 촬영 계획 체크리스트에 전달한다. 두 번째 실패를 기다리지 않는다.
- 두 번째 장면 이전에서 콘텐츠별 앱 코드 수정이 필요하면 "선언형" 주장을 철회하고 수정 범위를 기록한다.

## 7. 실제 성지로 옮길 때 재사용과 재저작

| 재사용 (설정·코드) | 재저작 (장소별) |
|---|---|
| 축 플래그, 상태 소유권, 자막·음소거·건너뛰기 경로, 기록 양식 | 스플랫·충돌 정합(기준점·단위·방향·시선 높이) |
| 스카이박스 설정 방식 | 하늘 분리 작업 자체, 수목·건물 경계 |
| 레일·트리거·구역 사전 로딩 계약 | 레일 경로, 필요 구역, 걷기 가능 구역·금지 경계·복귀점 |
| 인물 배치·표지 계약 | 인물 위치·외관·표현 승인 |
| 콘텐츠 데이터 스키마 | 사실·출처·해설문·검수 |

촬영·SfM·학습 파이프라인과 실제 역사 복원 비용은 이 단계에서 산정하지 않는다. 후속 촬영 계획에는 스카이박스용 하늘 자료 확보와 경계 재구성 입력 확보를 별도 항목으로 둔다(제안이며 검증된 촬영법이 아니다).
